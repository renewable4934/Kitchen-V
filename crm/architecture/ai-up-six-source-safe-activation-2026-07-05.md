## Текущая блокировка

### Browser / AI-UP access

Попытки открыть AI-UP через in-app browser automation завершались зависанием до получения вкладки. Прямой HTTP-запрос к AI-UP без browser cookies возвращает редирект на sign-in, то есть авторизованного API-доступа из shell нет.

Cookies AI-UP в профиле Codex обнаружены, но они зашифрованы. Значения cookies не выводились и не использовались. Попытка стандартной локальной расшифровки не дала рабочую авторизованную сессию.

### Gateway token

Локальный временный файл с новым approval token уже отсутствует. Без него нельзя повторить dry-run gateway и нельзя безопасно отредактировать AI-UP webhook URL. Значение token не выводилось.

### Integrations risk

Реальное включение project нельзя делать, пока одновременно остаются неизвестными или неподтверждёнными:

1. `AI-UP Controlled Gateway` может всё ещё содержать `dry_run=1`;
2. `AI-UP Direct CRM` может всё ещё быть подключён и писать напрямую в Bitrix24;
3. свежий active-source список на момент запуска не подтверждён.

Если запустить project в таком состоянии, контакты могут либо не попасть в Bitrix24, либо попасть в Bitrix24 напрямую, минуя safe gateway.

## Безопасные правила для первого контакта

При будущей активации каждый контакт из AI-UP должен идти только через controlled gateway и маркироваться без вводящих в заблуждение формулировок:

- `source = AI-UP`;
- `source_type = behavioral_interest`;
- `request_type = not_direct_request`;
- `do_not_claim_competitor_application = true`;
- наличие opt-out / do-not-call path;
- скрипт менеджера без утверждений вида «вы оставляли заявку у конкурента» или «вы были на конкретном сайте».

## Что нельзя делать сейчас

Нельзя:

1. включать AI-UP project вслепую;
2. включать production AI-UP pixel без официального snippet/public identifier;
3. оставлять прямую Bitrix integration активной рядом с controlled gateway;
4. считать старый UI-срез свежим перед платным запуском;
5. создавать тестовые сделки или контакты для обхода проверки.

## Как довести до запуска

Нужен короткий ручной recovery-шаг в авторизованном AI-UP кабинете:

1. открыть AI-UP project `Пегас`;
2. подтвердить, что active sources ровно шесть: `pegasmebel.ru`, `legokuhni.ru`, `kuhnihit.ru`, `rosta-mebel.ru`, `dekol-mebel.ru`, `ukuhni.ru`;
3. подтвердить лимит `1` у каждого source;
4. подтвердить, что phone sources и прочие competitor sources остановлены;
5. открыть integrations;
6. отключить или удалить `AI-UP Direct CRM`;
7. убедиться, что `AI-UP Controlled Gateway` указывает на production gateway без `dry_run=1`;
8. если URL gateway нельзя подтвердить, не запускать project;
9. только после этого включить project;
10. наблюдать первую identification и проверить, что она пришла в Bitrix24 через safe gateway;
11. остановить project после первой контрольной проверки, если есть любые сомнения по маршруту или формулировкам.
